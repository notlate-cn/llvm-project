# 10分钟看懂AI编译器做了些什么？

## 引言

当你写下一段深度学习代码并运行时，背后发生了什么？AI编译器如何将你的计算图转换成高效的硬件代码？本文通过一个具体案例，逐步解析AI编译器（以MLIR为例）的工作流程。

---

## 案例设定

**计算任务**：`output = (input1 + input2) * input3`

**数据规模**：shape = (1280, 64), dtype = float32

**目标硬件**：Ascend NPU（具有UB/GM内存层次，支持多核向量计算）

---

## 1. 用户代码（TensorFlow）

```python
import tensorflow as tf

# 输入数据
input1 = tf.placeholder(tf.float32, shape=(1280, 64))
input2 = tf.placeholder(tf.float32, shape=(1280, 64))
input3 = tf.placeholder(tf.float32, shape=(1280, 64))

# 计算图：add + mul
add_out = tf.add(input1, input2)
mul_out = tf.multiply(add_out, input3)

# 这就是AI编译器的输入
```

---

## 2. 计算图 → StableHLO方言

**发生了什么**：将TF计算图转换为MLIR的StableHLO方言表达。StableHLO是一种高层方言，保留了张量语义和操作意图。

```mlir
module @compute_graph {
  func @main(%arg0: tensor<1280x64xf32>,   // input1
             %arg1: tensor<1280x64xf32>,   // input2
             %arg2: tensor<1280x64xf32>) -> tensor<1280x64xf32> {  // input3

    // add操作
    %0 = stablehlo.add %arg0, %arg1 : tensor<1280x64xf32>

    // mul操作
    %1 = stablehlo.multiply %0, %arg2 : tensor<1280x64xf32>

    return %1 : tensor<1280x64xf32>
  }
}
```

**要点**：
- 保持了原始的计算语义
- 使用tensor抽象（无内存概念）
- 操作之间通过依赖关系连接

---

## 3. StableHLO → Linalg方言

**发生了什么**：转换为Linalg方言，为后续优化做准备。Linalg提供了更结构化的循环和计算表达。

```mlir
module @compute_graph {
  func @main(%arg0: tensor<1280x64xf32>,
             %arg1: tensor<1280x64xf32>,
             %arg2: tensor<1280x64xf32>) -> tensor<1280x64xf32> {

    // 初始化输出tensor
    %add_init = tensor.empty() : tensor<1280x64xf32>
    %mul_init = tensor.empty() : tensor<1280x64xf32>

    // add操作：generic表达
    %add_out = linalg.generic {
      indexing_maps = [
        affine_map<(d0, d1) -> (d0, d1)>,  // input1
        affine_map<(d0, d1) -> (d0, d1)>,  // input2
        affine_map<(d0, d1) -> (d0, d1)>   // output
      ],
      iterator_types = ["parallel", "parallel"]
    } ins(%arg0, %arg1 : tensor<1280x64xf32>, tensor<1280x64xf32>)
      outs(%add_init : tensor<1280x64xf32>) {
      ^bb0(%a: f32, %b: f32, %out: f32):
        %result = arith.addf %a, %b : f32
        linalg.yield %result : f32
    } -> tensor<1280x64xf32>

    // mul操作：generic表达
    %mul_out = linalg.generic {
      indexing_maps = [
        affine_map<(d0, d1) -> (d0, d1)>,  // input (add_out)
        affine_map<(d0, d1) -> (d0, d1)>,  // input3
        affine_map<(d0, d1) -> (d0, d1)>   // output
      ],
      iterator_types = ["parallel", "parallel"]
    } ins(%add_out, %arg2 : tensor<1280x64xf32>, tensor<1280x64xf32>)
      outs(%mul_init : tensor<1280x64xf32>) {
      ^bb0(%x: f32, %c: f32, %out: f32):
        %result = arith.mulf %x, %c : f32
        linalg.yield %result : f32
    } -> tensor<1280x64xf32>

    return %mul_out : tensor<1280x64xf32>
  }
}
```

**要点**：
- 显式表达了迭代空间（1280 × 64的二维循环）
- indexing_maps定义了数据访问模式
- 为图融合提供结构基础

## 4. Linalg方言上的图融合

**发生了什么**：将add和mul融合为一个操作，减少内存访问和kernel启动开销。

```mlir
// 融合后：单个generic操作完成 add + mul
%result = linalg.generic {
  indexing_maps = [
    affine_map<(d0, d1) -> (d0, d1)>,  // input1
    affine_map<(d0, d1) -> (d0, d1)>,  // input2
    affine_map<(d0, d1) -> (d0, d1)>,  // input3
    affine_map<(d0, d1) -> (d0, d1)>   // output
  ],
  iterator_types = ["parallel", "parallel"]
} ins(%arg0, %arg1, %arg2 : tensor<1280x64xf32>, tensor<1280x64xf32>, tensor<1280x64xf32>)
  outs(%init : tensor<1280x64xf32>) {
  ^bb0(%a: f32, %b: f32, %c: f32, %out: f32):
    // 计算融合：(a + b) * c
    %add = arith.addf %a, %b : f32
    %mul = arith.mulf %add, %c : f32
    linalg.yield %mul : f32
} -> tensor<1280x64xf32>
```

**优化效果**：
- 减少一次中间结果写回内存
- 单个kernel执行，减少启动开销
- 提高数据局部性

## 5. Linalg → AFIR方言（Ascend NPU方言）

AFIR是针对Ascend NPU定制的方言，基于AFIR执行以下硬件相关的优化，

### 5.1 循环合并

**发生了什么**：将二维循环(1280, 64)合并为一维循环(81920)

```mlir
// 合并前：iteration (1280, 64)
// 合并后：iteration (81920)

afir.loop_merge {
  src_iter = (1280, 64)
  dst_iter = (81920)
  merge_strategy = "flatten"
}
```

### 5.2 循环切分

**发生了什么**：按照硬件特征切分循环，映射到NPU的多核向量计算单元。

```mlir
// 切分配置：(10个核, 每核4次迭代, 每次2048元素)
// shape (81920) -> (10, 4, 2048)

afir.loop_tile {
  shape = (81920)
  tiled_shape = (10, 4, 2048)
  mapping = {
    dim_0: "block_x",      // 10个计算核
    dim_1: "unroll",        // 循环展开
    dim_2: "vector"         // 向量长度2048
  }

  // 生成嵌套循环
  for %block_idx in 0..10 {
    for %unroll_idx in 0..4 {
      for %vec_idx in 0..2048 {
        // 计算全局索引
        %global_idx = %block_idx * 4 * 2048 + %unroll_idx * 2048 + %vec_idx
        // 执行 add + mul
      }
    }
  }
}
```

**硬件映射**：
- **block维度**：分配给NPU的10个AI Core
- **unroll维度**：每个core内部循环展开
- **vector维度**：单次向量计算长度

### 5.3 向量化

**发生了什么**：将最内层的标量循环转换为向量操作，直接调用NPU的向量计算指令。

```mlir
// 向量化前：标量循环
for %vec_idx in 0..2048 {
  %a = %ub_in1[%vec_idx]
  %b = %ub_in2[%vec_idx]
  %c = %ub_in3[%vec_idx]
  %add = arith.addf %a, %b : f32
  %mul = arith.mulf %add, %c : f32
  %ub_out[%vec_idx] = %mul
}

// 向量化后：直接调用向量指令
// 假设NPU向量单元长度为256，则2048个元素需要8次向量调用
for %i in 0..8 {
  %offset = %i * 256

  // 提取向量view
  %vec_a = vector.load %ub_in1[%offset] : vector<256xf32>
  %vec_b = vector.load %ub_in2[%offset] : vector<256xf32>
  %vec_c = vector.load %ub_in3[%offset] : vector<256xf32>

  // 向量add（对应pyascir.add）
  %vec_add = afir.vector_add %vec_a, %vec_b : vector<256xf32>

  // 向量mul（对应pyascir.mul）
  %vec_mul = afir.vector_mul %vec_add, %vec_c : vector<256xf32>

  // 写回结果
  vector.store %vec_mul, %ub_out[%offset] : vector<256xf32>
}
```

**关键点**：
- `afir.vector_add` / `afir.vector_mul` 是支持向量化输入的操作
- 直接映射到NPU的向量计算单元（如Ascend的Vector单元）
- 消除了最内层循环，一次指令处理256个元素
- 向量长度由硬件特性决定（可配置为128/256/512等）

### 5.4 Tensor → Buffer转换

**发生了什么**：引入显式内存分配，区分GM（全局内存）和UB（统一缓冲区）。

```mlir
// 输入tensor转换为buffer（在GM中）
%gm_input1 = afir.alloc() : memref<1280x64xf32, @GM>
%gm_input2 = afir.alloc() : memref<1280x64xf32, @GM>
%gm_input3 = afir.alloc() : memref<1280x64xf32, @GM>

// 输出buffer（在GM中）
%gm_output = afir.alloc() : memref<1280x64xf32, @GM>

// UB临时空间（用于计算）
%ub_temp = afir.alloc() : memref<2048xf32, @UB>

// 数据搬运：GM -> UB
afir.copy(%gm_input1[%block_offset:%block_offset+2048], %ub_temp)
```

**内存层次**：
- **GM**：大容量全局内存，访问较慢
- **UB**：片上缓存，容量小但速度快

### 5.5 Buffer分配复用

**发生了什么**：mul的输入复用add的输出空间，减少UB占用。

```mlir
// 优化前：需要两个UB buffer
%ub_add_out = afir.alloc() : memref<2048xf32, @UB>
%ub_mul_out = afir.alloc() : memref<2048xf32, @UB>

// 优化后：复用同一个buffer
%ub_workspace = afir.alloc() : memref<2048xf32, @UB>

// add结果写入workspace
%ub_workspace = linalg.generic ... { addf } outs(%ub_workspace)

// mul复用workspace作为输入
%ub_workspace = linalg.generic ... { mulf } ins(%ub_workspace, ...) outs(%ub_workspace)
```

**AFIR完整表示**（融合了循环切分、向量化、Buffer转换、空间复用）：

```mlir
func @fused_add_mul_afir(%arg0: memref<1280x64xf32, @GM>,
                         %arg1: memref<1280x64xf32, @GM>,
                         %arg2: memref<1280x64xf32, @GM>)
    -> memref<1280x64xf32, @GM> {

  // 分配输出GM空间
  %output = afir.alloc() : memref<1280x64xf32, @GM>

  // 分配UB workspace（复用）
  %ub_workspace = afir.alloc() : memref<2048xf32, @UB>
  %ub_temp1 = afir.alloc() : memref<2048xf32, @UB>
  %ub_temp2 = afir.alloc() : memref<2048xf32, @UB>

  // 多核并行计算
  for %block in 0..10 {
    for %unroll in 0..4 {
      // 计算当前块的全局偏移
      %offset = %block * 4096 + %unroll * 2048

      // GM -> UB：搬运输入数据
      afir.copy(%arg0[%offset:%offset+2048], %ub_workspace)
      afir.copy(%arg1[%offset:%offset+2048], %ub_temp1)
      afir.copy(%arg2[%offset:%offset+2048], %ub_temp2)

      // UB上向量化计算（向量长度256）
      for %i in 0..8 {
        %vec_offset = %i * 256

        // 向量load
        %vec_a = vector.load %ub_workspace[%vec_offset] : vector<256xf32>
        %vec_b = vector.load %ub_temp1[%vec_offset] : vector<256xf32>
        %vec_c = vector.load %ub_temp2[%vec_offset] : vector<256xf32>

        // 向量计算：add + mul（结果复用workspace空间）
        %vec_add = afir.vector_add %vec_a, %vec_b : vector<256xf32>
        %vec_mul = afir.vector_mul %vec_add, %vec_c : vector<256xf32>

        // 向量store（写回workspace）
        vector.store %vec_mul, %ub_workspace[%vec_offset] : vector<256xf32>
      }

      // UB -> GM：写回结果
      afir.copy(%ub_workspace, %output[%offset:%offset+2048])
    }
  }

  return %output : memref<1280x64xf32, @GM>
}
```

## 6. Afir → PyAscendIR（NPU指令）

**发生了什么**：将buffer级的操作转换为NPU可执行的指令序列。

```python
# PyAscendIR伪代码

def kernel_fused_add_mul(input1_gm, input2_gm, input3_gm, output_gm):
    """
    NPU Kernel代码
    """
    # 获取核ID
    block_id = get_block_id()

    # 每个核处理4096个元素
    for unroll in range(4):
        offset = block_id * 4096 + unroll * 2048

        # 数据搬运指令：GM -> UB
        ub_in1 = load_gm_to_ub(input1_gm, offset, 2048)
        ub_in2 = load_gm_to_ub(input2_gm, offset, 2048)
        ub_in3 = load_gm_to_ub(input3_gm, offset, 2048)

        # 分配workspace（复用）
        ub_out = ub_in1  # 复用in1的空间

        # 向量计算指令：add + mul
        # 单次处理256个向量元素（假设向量长度为256）
        for i in range(8):
            vec_add = vector_add(ub_in1[i*256:(i+1)*256],
                                ub_in2[i*256:(i+1)*256])
            vec_mul = vector_mul(vec_add, ub_in3[i*256:(i+1)*256])
            ub_out[i*256:(i+1)*256] = vec_mul

        # 数据搬运指令：UB -> GM
        store_ub_to_gm(ub_out, output_gm, offset, 2048)

# 生成的二进制Kernel可以直接在NPU上执行
```

## 总结：AI编译器做了什么？

| 阶段 | 核心工作 | 带来的价值 |
|------|----------|-----------|
| **方言 lowering** | 将高层表示逐级转换为底层表示 | 分离关注点，每层专注特定优化 |
| **图融合** | 合并连续操作，减少中间结果 | 减少内存访问，提高数据局部性 |
| **循环变换** | 合并、切分、重排循环 | 适配硬件并行能力 |
| **向量化** | 标量循环转换为向量指令 | 充分利用SIMD单元，提升计算吞吐 |
| **内存优化** | 显式内存管理、空间复用 | 利用存储层次，减少带宽压力 |
| **指令生成** | 生成硬件特定指令 | 充分发挥硬件性能潜力 |

**AI编译器的本质**：将用户的高层计算意图，通过一系列语义保持的变换，最终翻译成能充分发挥硬件性能的低层代码。

## 延伸思考

1. **为什么需要多层方言？**
   - 每层方言解决特定层次的优化问题，降低编译器复杂度

2. **不同硬件后端如何支持？**
   - 前端 lowering 到 Linalg 是通用的
   - 后端只需实现 Linalg → TargetDialect 的转换

3. **如何验证正确性？**
   - 每步变换保持语义等价性
   - 可通过单元测试和数值对比验证
